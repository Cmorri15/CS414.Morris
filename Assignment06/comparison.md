In CS 372, I built my BST with a Node struct that had a value and left and right pointers, and I used nullptr to mean an empty tree. Every function started by checking whether the node was null, and I had to write a destructor to free the memory myself. For this assignment I used std::variant so the C++ code looks more like the OCaml type. Empty and Node are the two choices a tree can be, and std::visit with a set of lambdas works like a match ... with, where each lambda handles one case. One thing I liked is that the compiler makes you handle every case, so if I forget the Empty case it won't compile, instead of crashing later on a null pointer. I also didn't need a destructor because unique_ptr cleans up the nodes automatically.

The downside is that it was a lot more confusing to write. I needed the extra overloaded helper code just to make the lambdas work together, and the Node has to be held in a unique_ptr because a variant can't contain itself. The error messages were also much harder to read than with plain pointers. It acts a lot like pattern matching, but it's not as clean as OCaml, where you just write the cases. Overall it's safer than my CS 372 version, but it takes more code and is harder to read.
